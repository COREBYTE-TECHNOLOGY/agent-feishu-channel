# Corebyte Lark → GitHub 工作日志

实施任务：COREBYTE-TECHNOLOGY/corebyte#52。

## 功能与边界

这是桥接服务的**可选、默认关闭**模块。`main(configPath, workJournal)` 的第二参数由可信宿主注入；原 CLI 与其他机器人不受影响。当前唯一部署目标是 Jaime 的 corebyte-codex，GitHub 日志目标固定为 [corebyte#53](https://github.com/COREBYTE-TECHNOLOGY/corebyte/issues/53)。

每条已通过现有 Lark 白名单、交给模型执行的指令产生一条评论。记录人类发起者配置别名、指令摘要、UTC 时间、工作目录、工具名称与返回状态、有限文件路径、最后一组连续模型公开回复。流式 text 分片先在内存拼接，遇到新工具调用重置回复组；完成时整体脱敏后才保存和上传，不单独上传可能包含半截秘密的分片。内存组超过 64,000 字符则省略正文并明确提示。报告中提供的完成项、待办及 Issue/PR 引用予以保留，不编造报告未提供的关联。

“本轮执行结束”不是需求验收；取消、失败、重启结果不明分别标记。不会自动裁决业务、批准或合并 PR、关闭 Issue。系统不会声称未接收到结果的工具执行成功。

控制命令、普通群聊不会成为独立任务；`/stop` 优先走原控制链，取消结果更新原任务评论。日志网络调用不会成为 stop 路径的前置条件。不回补历史聊天。

## 数据最小化

- 排除思考、原始工具输出、附件、完整 shell 命令参数/脚本内容、完整工具 JSON。
- 仅记录 `path` / `file_path` 这类有限参数，并先脱敏；shell 调用只记录“已调用，参数未上传”。
- 已知凭证字面值、常见密钥格式、敏感赋值、URL 凭证等先过滤，再截断。宿主将现有机器人凭证用于本进程过滤，绝不把凭证传入模型或 GitHub。
- 用户与模型文本以惰性缩进代码显示，禁用意外 @ 通知、图片、HTML、伪造内部标记。UTF-8 分段预算保证单评论低于 60KB；动作最多 40 条，超限明确提示。
- 脱敏是尽力保护，不是完整 DLP。未知短密码、无标签或刻意编码的秘密仍可能漏检；用户不得把秘密发到群里。40/64 位裸十六进制值为保留 Git SHA 不统一删除。

## 写入与一致性

`sha256(chatId + "\n" + messageId)` 是稳定任务标识，真实 Lark ID 不进入日志存储；同一消息的已接收记录不能重复执行。接收前先同步写入本机 0700 目录/0600 文件，以原子替换保存，不等待 GitHub 网络。该存储并非经过断电测试的数据库。

每条任务：

1. 原子保存已接收记录；提交模型任务。
2. 后台按固定 Issue、预期登录用户和完整行标记查询已有评论。
3. POST 前持久化 `createAttempted`，POST 仅尝试一次。
4. POST 超时/响应丢失：后续只查标记，不盲目再次 POST。查到则继续更新；一直查不到则留待人工核对，不假称成功。
5. PATCH 前 GET 核对作者、Issue、标记及评论 ID，不覆盖无关评论；PATCH 响应丢失可再次写入同一完整快照。
6. 进度按 30 秒合并更新，开始/终态触发同步，每轮同任务最多写一次，终态通知最多等 12 秒。成功回传评论链接，未确认时明确“本机已保存，尚待同步”。

桥重启时，未终结任务记为“结果待核实”，不自动重新执行；脏记录继续补传。最多 2,000 个本机记录，满后拒绝新模型任务，需受控归档；不会自动删除用户记录。GitHub 查找最多 10,000 评论，超限报待处理而非错误断言不存在。

宿主使用现有 `gh` 登录，只允许固定仓库 `COREBYTE-TECHNOLOGY/corebyte` 与指定 Issue，固定 GitHub 主机、校验 `Jaimezz666` 登录。凭证不交给模型；不改变模型网络、目录与写入权限。请求通过 execFile 和 stdin JSON，不经 shell；单请求 10 秒超时、2MiB 响应上限。API 错误不携带原始正文/响应入日志。
